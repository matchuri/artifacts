# 자체 회원가입 기능

## 설명

- 사용자가 로그인 ID, 비밀번호, 이메일 인증, 필수 약관 동의, 닉네임과 초기 취향 입력을 거쳐 자체 계정을 생성하는 기능이다.
- 현재 프론트는 초기 취향까지 포함한 v2 가입 API를 사용한다. v1 가입 API는 호환용으로 유지한다.
- 회원가입 성공 후 사용자는 로그인 가능한 회원 상태가 된다.
- 로그인 ID와 닉네임은 중복 확인을 통해 서비스 내 고유성을 확보한다.
- 자체 회원가입은 소셜 로그인과 별개의 기본 가입 경로로 관리한다.

## 수용 기준

- 사용자는 로그인 ID 중복 여부를 확인할 수 있다.
- 사용자는 닉네임 중복 여부를 확인할 수 있다.
- 사용자는 이메일 인증을 완료한 뒤 회원가입을 제출할 수 있다.
- 사용자는 필수 약관 동의 정보를 포함해야 회원가입할 수 있다.
- 사용자는 맛과 조리 방식을 각각 하나 이상 선택한 뒤 초기 취향 프로필을 가입 요청에 포함한다.
- 회원 생성, 필수 약관 동의, 닉네임과 초기 취향 프로필 저장은 하나의 트랜잭션으로 처리하며 실패하면 모두 롤백한다.
- 중복 로그인 ID, 중복 닉네임, 유효하지 않은 이메일 인증 정보가 있으면 가입은 실패한다.
- 가입 성공 후 사용자는 로컬 로그인으로 인증할 수 있다.
- 가입 성공 후 자동 로그인하지 않고 완료 안내 후 `/login`으로 이동한다.

## 엣지케이스

- 이미 사용 중인 로그인 ID로 가입한다.
- 이미 사용 중인 닉네임으로 가입한다.
- 이메일 인증을 하지 않거나 만료된 인증으로 가입한다.
- 비밀번호 형식이 정책에 맞지 않는다.
- 필수 약관 동의 항목이 누락된다.
- 필수 취향을 선택하지 않거나 중복·존재하지 않는·비활성 취향 ID를 제출한다.
- 같은 요청을 여러 번 제출한다.

## 참고

- 관련 API
  - `GET /api/v1/members/exists/{loginId}`
  - `GET /api/v1/members/exists/nickname/{nickname}`
  - `POST /api/v1/auth/email`
  - `POST /api/v1/auth/email/confirm`
  - `POST /api/v2/members/signup`
- 관련 데이터
  - `members`
  - `member_agreements`
  - `auth_email_verifications`
  - `member_taste_profiles` 및 취향 연결 데이터
- 미정 사항: 이메일 인증 재시도 UX

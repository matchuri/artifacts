# 그룹 초대 기능

## 설명

- 그룹 `OWNER`가 닉네임 또는 링크로 다른 회원을 초대하는 기능이다.
- 닉네임 초대는 대상 회원이 받은 초대를 수락하거나 거절하는 요청 기반 흐름이다.
- 링크 초대는 `OWNER`가 UUID 토큰을 발급해 공유하고, 피초대자가 로그인 전에도 그룹 정보를 확인한 뒤 참여 여부를 선택하는 흐름이다.
- 클라이언트는 공유 URL의 `code` 쿼리 값에서 토큰을 추출한다. 서버는 URL 전체를 받거나 만들지 않고, 미리보기와 참여 API의 JSON request body에 담긴 `token`을 검증한다.
- 비로그인 피초대자는 토큰을 브라우저 세션에 보관하고 로그인 또는 회원가입을 마친 뒤 초대 화면으로 돌아온다. 서버는 로그인 과정에서 초대 토큰을 별도로 보관하지 않는다.
- 닉네임 초대 생성은 개인 실시간 이벤트로 알리고, 닉네임 초대 수락 또는 링크 참여로 멤버가 추가되면 그룹 멤버 참여 실시간 이벤트를 발행한다.

## 수용 기준

- `OWNER`는 닉네임으로 회원을 그룹에 초대할 수 있다.
- 사용자는 자신이 받은 그룹 초대 목록을 조회할 수 있다.
- 사용자는 초대를 수락하거나 거절할 수 있다.
- 수락하면 그룹 멤버십이 생성되거나 활성화된다.
- 거절하면 초대는 더 이상 참여에 사용할 수 없다.
- 이미 멤버인 사용자나 존재하지 않는 닉네임 초대는 실패한다.
- 닉네임 초대는 생성 시점부터 24시간 동안 응답할 수 있다.
- `ACTIVE` 그룹의 `ACTIVE` OWNER만 초대 링크를 신규 발급, 재발급, 조회할 수 있다.
- 초대 모달에 진입하면 현재 링크를 먼저 조회한다. 현재 활성 링크가 없으면 `200`과 `data: null`을 받고, 클라이언트가 신규 발급 API를 호출한다.
- 신규 링크는 현재 활성 링크가 없을 때만 발급되며, UUID 토큰과 그룹 ID, 만료 시각을 반환한다.
- 초대 링크는 발급 또는 재발급 시점부터 1일 동안 유효하다.
- 재발급하면 기존 활성 토큰은 즉시 만료되고 새 토큰이 발급된다.
- 현재 링크 조회는 만료되지 않은 최신 링크만 반환하며, 링크 조회 자체로 새 링크를 발급하지 않는다.
- 피초대자가 공유 URL에 진입하면 로그인 여부와 관계없이 공개 미리보기 API를 호출한다. 미리보기는 그룹명, 방장의 현재 닉네임, 활성 그룹원 수(방장 포함)만 반환하며 그룹 참여나 링크 상태 변경을 일으키지 않는다.
- 로그인한 피초대자에게 참여 여부를 묻는다. 수락하면 Bearer 인증과 링크 토큰을 사용해 참여 API를 호출하고, 거절하거나 화면을 나가면 서버의 그룹 상태는 바뀌지 않는다.
- 비로그인 피초대자에게 로그인 필요 안내와 로그인·나가기 선택지를 보여준다. 로그인 선택 시 토큰을 브라우저 세션에 보관하고 로그인 또는 회원가입을 진행한 뒤, 보관한 토큰으로 초대 화면에 재진입해 미리보기를 다시 조회한다. 실제 그룹 참여는 로그인 후 사용자가 수락했을 때만 요청한다.
- 참여 API는 로그인한 활성 회원만 사용할 수 있다. 필수 약관 동의와 닉네임 설정을 완료하지 않은 회원은 해당 온보딩을 마쳐야 참여할 수 있다.
- 미리보기와 참여는 모두 링크의 존재, 만료 여부와 그룹 `ACTIVE` 상태를 검증한다. 토큰은 UUID 형식이어야 한다.
- 링크 참여 시 신규 멤버십은 `MEMBER`, `ACTIVE`로 생성되고, 과거 `LEFT` 멤버십은 같은 멤버십을 재활성화한다.
- 이미 `ACTIVE` 멤버인 사용자의 링크 참여는 중복 참여로 실패한다.
- 그룹이 삭제되면 남아 있는 활성 초대 링크도 즉시 만료된다.
- 서버는 완성된 초대 URL을 만들지 않고 `groupId`, `token`, `expiresAt`만 반환한다. 공유 URL 조합, 토큰의 브라우저 세션 보관, 비회원 로그인 유도, 로그인 후 초대 화면 복귀는 클라이언트가 담당한다.

## 엣지케이스

- 일반 멤버가 초대를 생성한다.
- 존재하지 않는 닉네임을 초대한다.
- 이미 그룹에 속한 사용자를 초대한다.
- 이미 응답한 초대에 다시 응답한다.
- 그룹이 삭제된 뒤 초대에 응답한다.
- 초대 알림 이벤트 수신이 실패한다.
- 일반 멤버나 그룹 외 사용자가 링크를 발급, 재발급, 조회한다.
- 활성 링크가 있는데 신규 링크 발급을 요청한다.
- 활성 링크가 없는데 현재 링크를 조회한다. 조회는 오류 대신 `200`과 `data: null`을 반환한다.
- 활성 링크가 없는데 재발급을 요청하면 `404 GROUP_INVITE_LINK_NOT_FOUND`를 반환한다.
- 다른 요청이 먼저 링크를 발급해 신규 발급이 `409 GROUP_INVITE_LINK_ALREADY_EXISTS`로 실패하면 클라이언트는 현재 링크를 다시 조회할 수 있다.
- UUID 형식이 아닌 토큰으로 미리보기 또는 참여를 요청하면 `400 COMMON_INVALID_BODY_FIELD`를 반환한다.
- 존재하지 않는 토큰으로 미리보기 또는 참여를 요청하면 `404 GROUP_INVITE_LINK_NOT_FOUND`를 반환한다.
- 만료됐거나 재발급으로 폐기된 이전 토큰으로 미리보기 또는 참여를 요청하면 `409 GROUP_INVITE_LINK_EXPIRED`를 반환한다.
- 인증하지 않은 사용자가 링크 참여 API를 호출하면 `401 AUTH_TOKEN_MISSING`을 반환한다.
- 링크가 가리키는 그룹이 `ACTIVE` 상태가 아니면 미리보기와 참여를 `409 GROUP_NOT_ACTIVE`로 거절한다. 그룹 삭제 시 남아 있는 활성 링크는 만료된다.
- 미리보기에는 성공했지만 로그인 또는 회원가입 중 링크가 만료되거나 재발급된다. 복귀 후 미리보기와 참여 단계에서 다시 유효성을 확인한다.
- 로그인 또는 회원가입을 중단하거나 브라우저 세션의 토큰이 사라져 초대 화면에 복귀할 수 없다.
- 이미 `ACTIVE` 그룹원인 피초대자가 참여를 요청하면 `409 GROUP_ALREADY_JOINED`를 반환하고, `LEFT` 그룹원은 재참여한다.
- 토큰 충돌로 고유 토큰 생성에 5회 연속 실패한다.

## 참고

- 닉네임 초대 API
  - `POST /api/v1/groups/invites/nickname`
  - `GET /api/v2/invites/me`
  - `GET /api/v1/invites/me/exists`
  - `POST /api/v1/groups/invites/{inviteId}/response`
- 링크 초대 API
  - `POST /api/v1/groups/{groupId}/invite-link`
  - `POST /api/v1/groups/{groupId}/invite-link/reissue`
  - `GET /api/v1/groups/{groupId}/invite-link`
  - `POST /api/v1/groups/invite-links/preview` (인증 불필요, body: `token`)
  - `POST /api/v1/groups/invite-links/join`
- 실시간 이벤트 API
  - `GET /api/v1/realtime/events`
  - `GET /api/v1/groups/{groupId}/realtime/events`
- 관련 데이터
  - `group_invites`
  - `group_invite_links`
  - `group_room_members`
  - `group_rooms`
  - `members`
- 공유 URL 예시: `https://matchuri.com/groups/invite-link/preview?code=<UUID 토큰>`. 경로와 `code` 쿼리 값은 클라이언트가 해석하며 백엔드 API 경로와는 별개다.
- 현재 frontend 코드에서는 링크 발급·공유 UI, 초대 URL 진입 화면, 로그인 후 토큰 복원 및 참여 흐름이 확인되지 않는다.
- 미정 사항: 닉네임 초대 취소 기능, 닉네임 검색/자동완성 지원 여부

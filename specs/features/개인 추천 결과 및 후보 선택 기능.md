# 개인 추천 결과 및 후보 선택 기능

## 설명

- 로그인한 사용자가 자신이 요청한 개인 추천의 상태와 후보를 확인하고, 후보 하나를 최종 메뉴로 선택하는 기능이다.
- 상세 조회는 추천 상태, 종료 시각, 위치 컨텍스트, 후보 목록, 최종 선택 후보를 함께 반환한다.
- 후보는 후보 ID, 메뉴 ID, 메뉴명, 대표 이미지, 순위, 추천 점수를 포함한다.
- 추천이 종료되었더라도 소유자는 상세와 후보를 다시 조회할 수 있지만, 최종 선택은 유효한 `OPEN` 추천에서만 가능하다.
- MVP에서는 후보별 추천 이유나 결과 요약 문구를 제공하지 않는다.

### 정량 제약사항

- 한 추천의 후보 수는 최대 3개이며, 제외 조건을 통과한 메뉴가 부족하면 0~2개만 반환될 수 있다.
- 후보 순위는 1부터 시작한다. 알고리즘의 내부 합산 점수 내림차순으로 정렬하고, 내부 합산 점수가 같으면 메뉴 ID 오름차순으로 순서를 확정한다.
- 외부에 노출하는 추천 점수는 0~100 범위로 정규화하고 소수점 첫째 자리까지 반환한다.
- 미선택 `OPEN` 추천은 `requestedAt + 24시간`부터 만료로 판정한다.
- 선택 위치를 전달할 때 위도는 -90~90, 경도는 -180~180, 검색 반경은 0m 이상이어야 하며 주소는 공백이 아닌 255자 이하 문자열이어야 한다.
- 사용자에게 제공되는 검색 반경은 1km, 3km, 5km이다.

## 수용 기준

- 로그인한 사용자는 자신이 소유한 추천 ID로 상세와 후보 목록을 조회할 수 있다.
- 상세에는 `id`, `status`, `closedAt`, `contextJson`, 후보 목록, `selectedCandidateId`가 포함된다.
- 후보 목록은 `rankNo` 오름차순으로 반환되며 대표 이미지가 없으면 `thumbnailUrl`은 `null`이다.
- 조회 시점에 24시간 만료 기준을 넘긴 미선택 `OPEN` 추천은 `EXPIRED`와 `closedAt`이 반영된 상태로 반환된다.
- 최종 선택 요청의 `selectedCandidateId`는 양수인 필수값이며, 해당 추천에 속한 후보여야 한다.
- 선택 성공 시 추천 상태는 `SELECTED`가 되고 `closedAt`과 `selectedCandidateId`가 기록된다.
- 선택한 메뉴에는 해당 추천을 참조하는 `CHOOSE` 행동 로그가 1건 저장된다.
- 위치 필드 `latitude`, `longitude`, `radiusMeters`, `address`는 모두 선택 입력이다. 네 필드가 모두 유효하게 전달된 경우에만 위치 스냅샷을 `contextJson`에 저장한다.
- 위치 필드가 없거나 일부만 전달되어도 후보 선택은 성공하며, 위치 스냅샷은 저장하지 않는다.
- 선택 결과 갱신과 `CHOOSE` 로그 저장은 하나의 요청 처리 단위로 수행한다.
- `SELECTED`, `REROLLED_WITH_SKIP`, `REROLLED_WITHOUT_SKIP`, `EXPIRED`, `FAILED` 상태의 추천은 다시 선택할 수 없다.

## 엣지케이스

- 존재하지 않거나 다른 사용자가 소유한 추천 ID를 조회한다.
- 요청한 후보 ID가 존재하지 않거나 다른 추천에 속해 있다.
- 추천이 이미 선택, 재요청, 만료 또는 실패로 종료되었다.
- 추천이 선택 요청 시점에 정확히 24시간 만료 경계에 도달했다.
- 필터를 통과한 후보가 없어 후보 목록이 비어 있다.
- 후보 메뉴의 대표 이미지가 없거나 조회 시점에 메뉴 정보가 변경되었다.
- 위치 필드 일부만 전달하거나 범위 밖 좌표, 음수 반경, 공백 주소, 255자를 초과한 주소를 전달한다.
- 같은 추천에 대해 선택 요청이 동시에 또는 반복해서 들어온다.

  - `member_menu_actions`, `menu_items`

  - 후보별 추천 이유 제공 시점과 표현 방식

  - 만료되었거나 후보가 없는 결과 화면 처리
  - 동시 선택 요청의 서버 측 잠금 또는 멱등성 보장 방식

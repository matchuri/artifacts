# 개인 추천 재요청 기능

## 설명

- 사용자가 현재 후보가 마음에 들지 않거나 취향 입력을 바꾼 뒤 새 개인 추천을 받는 기능이다.
- 재요청은 기존 추천을 재사용하지 않고 source 추천을 종료한 뒤 새 추천 실행 단위와 후보를 생성한다.
- `NOT_SATISFIED`는 기존 후보를 당분간 다시 보여주지 않는 의사 표현이고, `INPUT_CHANGED`는 변경된 최신 취향 프로필로 다시 계산하는 흐름이다.
- source 추천과 새 추천 사이의 연결 ID는 별도로 저장하지 않으며, 두 실행은 각각 추천 실행 데이터로 남는다.

### 정량 제약사항

- `rerollType`은 `NOT_SATISFIED`, `INPUT_CHANGED` 두 값만 허용한다.
- source 추천은 `requestedAt + 24시간` 전의 미종료 `OPEN` 상태여야 한다.
- `NOT_SATISFIED` 재요청은 source 후보 전체에 후보별 `SKIP` 로그를 남기므로 한 번의 재요청에서 0~3건의 로그가 생성된다.
- `SKIP` 로그가 생성된 메뉴는 로그 생성 시각부터 24시간 동안 후보에서 제외되며, 24시간 경계부터 다시 후보가 될 수 있다.
- 새 추천 후보는 최대 3개이며, 제외 조건 때문에 0~2개만 생성될 수 있다.
- 새 후보 계산에서도 최근 최종 선택 이력 최대 3건의 메뉴를 제외한다.
- 서버에는 사용자별 또는 추천별 재요청 횟수 제한이 현재 없다.

## 수용 기준

- 로그인한 사용자는 자신이 소유한 유효한 `OPEN` 추천에 대해 재요청할 수 있다.
- `rerollType`은 필수 입력이다.
- `NOT_SATISFIED` 재요청은 source 후보 전체에 `SKIP` 행동 로그를 남기고 source 추천을 `REROLLED_WITH_SKIP`으로 종료한다.
- `INPUT_CHANGED` 재요청은 `SKIP` 로그 없이 source 추천을 `REROLLED_WITHOUT_SKIP`으로 종료한다.
- `INPUT_CHANGED`는 재요청 시점에 저장된 최신 취향 프로필을 사용한다.
- 재요청 성공 시 새 추천은 별도 ID와 `OPEN` 상태로 생성되며 새 후보 목록을 반환한다.
- source 추천의 `closedAt`과 새 추천의 `requestedAt`을 각각 기록한다.
- 이미 선택·재요청·만료·실패로 종료된 추천은 재요청할 수 없다.
- 시간상 만료된 source 추천은 먼저 `EXPIRED`로 전환한 뒤 재요청을 거절한다.

## 엣지케이스

- 존재하지 않거나 다른 사용자가 소유한 source 추천을 재요청한다.
- 종료된 추천 또는 정확히 24시간 만료 경계에 도달한 추천을 재요청한다.
- `rerollType`을 누락하거나 지원하지 않는 값을 보낸다.
- `NOT_SATISFIED` source 추천의 후보 목록이 비어 있다.
- 기존 후보, 제한 재료, 비선호 메뉴, 최근 선택 메뉴를 제외한 뒤 새 후보가 부족하거나 없다.
- 취향 프로필 저장은 성공했지만 이어지는 `INPUT_CHANGED` 재요청이 실패한다.
- source 종료 또는 `SKIP` 저장 뒤 새 추천 생성이 실패한다.
- 재요청 버튼을 빠르게 여러 번 누르거나 동일 source에 동시 요청을 보낸다.

## 참고

- 관련 API
  - `POST /api/v1/personal/recommendations/{requestId}/reroll`
  - `PATCH /api/v1/members/me/taste-profile`
- 관련 데이터
  - `personal_recommendations`
  - `personal_recommendation_candidates`
  - `member_menu_actions`
  - `member_taste_profiles`
- 미정 사항:
  - 제품 차원의 재요청 횟수 제한과 버튼 노출 정책
  - `SKIP` 제외 기간의 사용자 안내 방식
  - 취향 변경 저장 후 자동 재요청 여부
  - 새 추천 생성 실패 시 source 종료와 `SKIP` 로그의 원자성·복구 정책
  - 동시 재요청의 서버 측 잠금 또는 멱등성 보장 방식
